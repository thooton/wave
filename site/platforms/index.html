01 / USB GUIDE

Before you connect.

Check the model in Settings → About phone: XP3800, Android 8.1. Other XP3 phones are not interchangeable. No browser flashing or restore workflow is verified here.

Keep a way back

Back up contacts, messages, photos and other personal files. A stock boot image is not a copy of your personal data. Keep two copies of the untouched image off-device, along with the original SHA-256, serial and firmware build. Do not use an image from another phone, even one of the same model.

Computer and cable

Use a data cable and USB port you trust, and close other tools holding the device. An HTTPS page in a WebUSB-capable desktop browser such as Chrome or Edge can request a USB device; check the site and device before approving. Firefox and Safari do not supply that API. USB is not needed for the app setup generator.

Linux

Use the distribution’s Android udev rules for the debugging interface. Check the vendor/product identifiers with lsusb. For the XP3800 in Qualcomm service mode, these two narrow rules allow a logged-in desktop user to access only 05c6:9008 and prevent ModemManager from probing it:

# /etc/udev/rules.d/70-wave-xp3.rules
SUBSYSTEM=="usb", ATTR{idVendor}=="05c6", ATTR{idProduct}=="9008", TAG+="uaccess"
SUBSYSTEM=="usb", ATTR{idVendor}=="05c6", ATTR{idProduct}=="9008", ENV{ID_MM_DEVICE_IGNORE}="1"

Ask the system administrator to reload udev rules, then reconnect. Do not make every USB device world-writable or disable ModemManager system-wide. 05c6:900e is a crash-dump interface, not the service interface.

Windows

WebUSB needs the chosen USB interface to use WinUSB. A Qualcomm serial driver can serve a desktop recovery tool without being usable by WebUSB. If a supported service procedure calls for WinUSB, record the current driver and confirm the exact hardware ID in Device Manager. Driver tools such as Zadig can change the wrong interface: never replace the parent composite device’s driver or a driver shared with other hardware.

macOS and ChromeOS

Chromium desktop browsers generally do not need a separate WinUSB-style driver. Enterprise policies, another program using the device or a charge-only cable can still prevent access. No device flow has been validated on these platforms in this release.

Protect debugging access

USB debugging lets an authorized computer run commands on the phone. Only approve a fingerprint for your own computer. When done, disable debugging and revoke authorizations you no longer use in Developer options.
